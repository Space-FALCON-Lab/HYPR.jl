# Validation and limits

The extraction preserves source calculations and operation order, with a targeted
exception: search code is called through the new package boundary. The standalone
serial search is extracted from the robot-arm loop. RPO calls the core particle
update kernel and shared swarm policy; its specialized outer schedule remains in
the optional extension. These variants are not silently unified.

The accepted comparison consists of four bounded RPO cases and two robot-arm
cases, including the random values consumed after each result. Its serialized
fingerprint is `9b25466fd812cf70330d3379a7b2071bcea0b93c3c364051959e698cdc3aed38`.
The extracted implementation reproduces that fingerprint byte-for-byte. Larger integration and
independent review are separately recorded; this hash is not full mission,
performance, arbitrary-thread, native atmosphere or paper-claim acceptance.

Preserve the known RRT adaptive sampling limitation, retimer fallback warnings,
shared optimizer dependencies and the finite scope of previous physics tests.
No numerical acceptance threshold is changed by packaging. Wall-clock timeout
runs can stop at different points and are not claimed bitwise repeatable.

## Arithmetic regression tests

`test/arithmetic_regressions.jl` compares exact Float64 bit patterns and subsequent
random draws against records captured from the accepted extraction's search
kernels at commit `129abe677c6c26c83fc035eb07161871bcd50a69`, using Julia 1.12.3.
The fixture records serial search state, evaluation order, culling and stopping,
and the threaded particle update with separate particle RNGs. Both acceleration
terms are nonzero. The fixture is retained data, not regenerated by CI.

`python3 test/run_mutation_controls.py` runs an unchanged positive control and six
intentionally altered kernels in separate processes. It checks evaluation order,
culling versus stopping, the final move, floating-point operation order, and RNG
draw assignment. Each altered kernel must fail a reference assertion; a package
loading error does not count as detection. CI runs the controls with one and four
threads. Exact bit comparisons describe this pinned fixture and supported runtime;
they do not establish arbitrary-platform or arbitrary-RNG reproducibility.

## Coverage of core and integration code

The coverage gate inventories every Julia source file in `src/` and `ext/`, checks
its hash, and merges line counts from the core tests at one and four threads and
SpaceAGORA's maintained RPO and robot-arm consumer tests. The integration tests
also compare the configured sampling wrappers with their shared kernels.

The gate requires **90% overall and 80% in every executable file**. No moved file
is excluded. `src/HYPR.jl` is module wiring with no measured executable lines;
its inventory entry remains visible without a fabricated percentage. Julia can
leave a never-compiled function unmeasured, so named functions, anonymous
`function` forms, arrow closures and `do` callbacks are inventoried. An entirely
unmeasured body is rejected rather than silently omitted from the denominator.
For closures the inspected span is the body, excluding a separate creation or
call line. Named definitions include their declaration line because Julia can
attribute a short-form body to that line. This remains line coverage: expressions sharing a source
line cannot be distinguished by line counters alone.
These are line-coverage checks, not branch coverage or scientific acceptance.

The configured RRT* wrapper always supplies a refinement callback, so its
fallback cost callback is not exercised by normal configured runs. A separate
process tests that supplied callback against the configured polyline objective,
then delegates to the unchanged shared engine. Its observer method exists only
in that test process. This checks the callback contract; it does not establish a
production fallback path for configured RRT*.

Run against separate core and integration environments:

```sh
python3 scripts/run_coverage.py --core-project /path/to/core-env \
    --integration-project /path/to/integration-env --output /path/to/coverage-output
```

The runner requires an empty output directory, clears old counters for this
checkout, records each real exit status, and stops on a failed stage. It retains
the raw counters alongside the report for independent inspection. Python 3.11 or later is required. The report lists all
files, counts and thresholds. `python3 test/test_coverage_gate.py` checks the gate's
rejection of low coverage, missing or stale counters, omitted source, unmeasured
functions and failed test stages.

CI uses the reviewed SpaceAGORA service-provider revision. Published-source
installation and passing hosted CI on the release pair are separate requirements.
The release record and integration PR identify that pair and its results; local
passing results alone are not release acceptance.
